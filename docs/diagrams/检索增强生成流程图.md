# 检索增强生成流程图

用户只选择聊天模型。后端从受控模型目录派生对应的向量模型，并在同一资料的多套 1024 维向量中选择匹配的向量空间。

```mermaid
flowchart TD
    A["教师上传或更新学习资料"] --> B["学习服务登记资料并创建索引任务"]
    B --> C{"模块是否已发布？"}
    C -- "否" --> C1["等待模块发布"]
    C -- "是" --> D["AI worker 读取 MinIO 或本地资料"]
    D --> E["提取并标准化文本"]
    E --> F{"内容提取成功？"}
    F -- "否" --> F1["保存失败原因并允许重试"]
    F -- "是" --> G["统一切分模型无关的知识块"]

    G --> H["读取已配置且启用的 Embedding 模型"]
    H --> I1["Gemini Embedding 001<br/>1024 维"]
    H --> I2["GLM Embedding-3<br/>1024 维"]
    H --> I3["OpenRouter Embedding<br/>1024 维"]

    I1 --> J["按知识块、模型和版本 Upsert 多向量"]
    I2 --> J
    I3 --> J
    J --> K["更新每个模型的索引覆盖率和状态"]

    K --> L["用户打开课程聊天"]
    L --> M["前端展示聊天模型及配对向量模型"]
    M --> N["用户选择 Gemini、GLM 或 OpenRouter 聊天模型"]
    N --> O["请求始终携带选中的 chat model_id"]
    O --> P["后端解析聊天模型并派生 pairedEmbeddingModelId"]

    P --> Q{"该课程的配对向量是否就绪？"}
    Q -- "回填中或失败" --> Q1["返回明确索引状态<br/>不伪装成 RAG"]
    Q -- "模块没有资料" --> Q2["进入明确标识的普通聊天模式"]
    Q -- "是" --> R["用配对模型生成查询向量"]

    R --> S["按课程或模块权限、模型和版本过滤向量"]
    S --> T["向量相似度检索、标题匹配、去重和得分过滤"]
    T --> U["把检索结果与来源组装为上下文"]
    U --> V["使用用户选择的聊天模型生成回答"]
    Q2 --> V
    V --> W["返回实际聊天模型、向量模型、检索模式和来源"]
    W --> X["保存会话、检索记录和脱敏遥测"]
```

约束：

- 维度相同的不同模型也不能混用向量。
- 新增 Provider Key 后，为现有知识块异步回填该 Provider 的向量；用户切换模型不会临时重新切分资料。
- 一个 Provider 的索引失败不影响其他 Provider 已经完成的向量。
- AI 测验检索使用管理员默认聊天模型配对的向量模型；向量未就绪时返回结构化错误。
