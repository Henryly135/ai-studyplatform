# 多向量迁移与回填

升级到 1024 维多向量表后，旧的单向量列只用于回滚，检索不会继续读取它。首次升级必须在对外演示前完成一次回填。

管理员保存并启用 Gemini、GLM 或 OpenRouter 凭据时，服务会先把凭据健康状态置为
`unknown` 并排队一次历史资料检查。随后必须执行 Provider 健康检查；该检查同时
调用真实聊天模型和配对的 1024 维 Embedding。两者成功后状态变为 `ready`，服务会
再次触发历史资料回填，确保新增向量空间不会因初始健康门禁而遗漏。`unknown`、
`failed` 或 `quota` 状态下，普通聊天、测验与回填 worker 都不会调用该供应商。

需要手工补偿、版本迁移或演示前强制核对时，也可以调用：

```http
POST /api/ai/admin/telemetry/index-jobs/reindex-all
Authorization: Bearer <admin-token>
```

该接口会为已有规范化资料创建回填任务。若某份资料正在运行，会复制该资料最新有效任务的内容快照并排队一个后续任务；若更新的上传仍是 `queued` 或 `blocked`，则保留它而不创建旧 source 回填，因为它会在执行时读取最新 Provider 列表。任务创建以 material 级事务锁串行化，已成功的新版本也始终优先于旧运行任务。即使首次上传尚未创建知识源，也不会漏掉新 Provider。较旧任务在任何写入边界发现更新任务后会回滚待写数据并转为 `superseded`。

Demo 环境可让预检脚本自动触发回填并等待课程覆盖率达到 100%：

```bash
export DEMO_ADMIN_ACCESS_TOKEN='replace-with-admin-token'
export DEMO_ACCESS_TOKEN='replace-with-course-access-ai-chat-token'
export DEMO_COURSE_UUID='replace-with-course-uuid'
export DEMO_MODULE_UUID='replace-with-accessible-published-module-uuid'
export DEMO_TRIGGER_BACKFILL=true
bash scripts/demo-preflight.sh
```

`DEMO_ADMIN_ACCESS_TOKEN` 用于调用治理回填接口和读取 Provider 状态；`DEMO_ACCESS_TOKEN` 必须属于能访问指定课程且拥有 `AI_CHAT_USE` 的教师或学习者，用于课程与模块范围的 `/api/ai/models` 覆盖检查。`DEMO_MODULE_UUID` 必须指向该账号可访问的已发布模块，因为学习者的 AI 权限校验不允许缺少模块上下文。两种令牌都必填且不能互相替代，预检不会回显令牌。PowerShell 使用相同环境变量后运行 `scripts/demo-preflight.ps1`。预检未通过时不得把课程 RAG 标记为可演示。

新增或更换并启用任一 Provider 凭据会自动触发回填；修改配对 Embedding 模型或版本后仍应手工调用回填接口。任务会复用内容哈希和 chunk 指纹一致的规范化资料，只补缺失或失败的模型向量，不会删除已经成功的其他 Provider 向量。

资料内容发生变化但所有向量调用都失败、或当前没有可用向量模型时，旧内容会被标为 stale 并停止参与检索，避免返回已经被替换的资料。任务保留在可重试路径；已有其他 Provider 的成功向量仅在内容未变化时继续可用。
