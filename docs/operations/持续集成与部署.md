# CI/CD 说明

本文档记录当前持续集成和部署流程。工作流文件名、分支名、命令和 secret 名保持原样。

## 概览

- CI 由 GitHub Actions 执行，工作流文件位于 `.github/workflows/ci.yml`。
- 部署通过 `workflow_dispatch` 手动触发。
- `main` 是主分支。
- CI 会检查前端、后端、共享包、Docker Compose 配置和基础安全规则。
- 生产模式下，服务会拒绝占位密钥、弱 JWT 密钥、缺失 HTTPS 前端地址和未配置的核心依赖。

## 分支规则

- 功能开发可使用 `feature/**`。
- 修复可使用 `fix/**`。
- 重构可使用 `refactor/**`。
- 合并前应保证 CI 通过。

## CI 触发

CI 通常在以下情况运行：

- 推送到主要分支或功能分支。
- 创建或更新 pull request。
- 手动触发工作流。

## CI 检查内容

### 共享包

- 安装 `packages/platform_common`。
- 执行配置和安全相关单元测试。

### 前端

```bash
npm ci
npm run lint
npm test -- --run
npm run build
npm audit
```

### 后端服务

分别执行：

- `identity-service` 测试。
- `learning-service` 测试。
- `communication-service` 测试。
- `ai-service` 测试。

### Docker 与基础设施

- 解析 `infra/docker-compose.yml`。
- 检查 nginx 配置。
- 检查 `.env.example` 是否保留占位值。
- 检查 MinIO 私有 bucket 策略。
- 检查生产安全配置是否 fail-fast。

## 部署流程

部署工作流由 GitHub Actions 手动触发。触发前需要确认：

- 目标分支已经通过 CI。
- GitHub Secrets 已配置。
- 目标机器 Docker 环境可用。
- `.env` 或部署环境变量已经更新。
- 数据库迁移和初始化脚本与当前版本匹配。

## 部署脚本

脚本位于 `scripts/`。执行时应：

- 拉取指定分支。
- 写入或读取环境变量。
- 构建镜像。
- 启动 Docker Compose。
- 检查服务健康状态。
- 保留失败日志，方便回滚和排查。

## 必要密钥

GitHub Secrets 至少应包含：

- SSH 连接信息。
- 数据库密码。
- JWT 密钥。
- 内部服务密钥。
- SMTP 配置。
- Gemini API key。
- MinIO 访问密钥。

真实值不得写入仓库。
