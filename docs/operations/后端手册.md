# 后端运行说明

本文档记录后端服务边界、认证规则、常用接口关系和前后端集成注意事项。路径、服务名、权限码、字段名和命令保持原样。

## 服务边界

| 服务 | 目录 | 主要职责 | 依赖 |
| --- | --- | --- | --- |
| `identity-service` | `services/identity-service` | 注册、登录、邮箱验证、密码重置、用户、角色、权限、教师审批、教师邀请 | MySQL |
| `learning-service` | `services/learning-service` | 课程、模块、资料、进度、报名、邀请、测验、教学分析 | MySQL、Redis、MinIO、Celery |
| `communication-service` | `services/communication-service` | 课程论坛、评论、通知、通知状态 | MySQL、Celery |
| `ai-service` | `services/ai-service` | AI 对话、RAG、资料索引、测验生成、学习画像、AI 观测 | PostgreSQL、pgvector、Redis、Celery、MinIO |

## 本地路由

本地 Docker Compose 通过 nginx 聚合服务。前端通常只调用一个基础地址：

```text
http://localhost:${NGINX_PORT}/api/...
```

路由转发规则：

| 外部路径 | 后端服务 |
| --- | --- |
| `/api/` | `identity-service` |
| `/api/learning/` | `learning-service` |
| `/api/communication/` | `communication-service` |
| `/api/ai/` | `ai-service` |
| `/learning-materials/` | MinIO 私有资料代理，匿名直连应被拒绝 |

## 认证与权限

- 用户登录后获得 JWT。
- 前端通过 `Authorization: Bearer <token>` 调用受保护接口。
- 后端必须做权限校验，不能只依赖前端隐藏按钮。
- 学生、教师、管理员的能力边界以后端权限为准。
- 内部服务调用应使用内部密钥或服务间鉴权，不暴露给浏览器。

常见权限码：

- `COURSE_READ`
- `COURSE_ENROLL`
- `COURSE_MANAGE`
- `QUIZ_ATTEMPT`
- `AI_CHAT`
- `ADMIN_USER_MANAGE`
- `ADMIN_AI_TELEMETRY`

## 常见错误

| 状态码 | 含义 | 常见原因 |
| --- | --- | --- |
| `400` | 请求无效 | 请求体不完整或业务状态不允许 |
| `401` | 未认证 | token 缺失、过期或格式错误 |
| `403` | 无权限 | 角色不匹配、课程不属于当前教师、学生访问管理接口 |
| `404` | 不存在 | UUID 错误或资源已删除 |
| `409` | 状态冲突 | 重复报名、重复发布、重复处理 |
| `422` | 参数校验失败 | 字段类型或格式不符合 schema |
| `503` | 外部服务不可用 | Gemini、GLM、OpenRouter、SMTP、MinIO、数据库或 Redis 不可用 |

## 主要业务链路

### 身份服务

- `POST /auth/register`：注册用户。
- `POST /auth/login`：登录。
- `GET /auth/me`：读取当前用户。
- `GET /auth/me/permissions`：读取当前用户权限。
- `POST /auth/forgot-password` 与 `POST /auth/reset-password`：密码重置。
- `GET /auth/invite/educator/validate` 与 `POST /auth/register-educator-invite`：教师邀请注册。
- `/admin/users/*`：管理员用户管理。
- `/admin/educator-approvals/*`：教师审批。

### 学习服务

- 课程目录和详情用于学生浏览课程。
- 课程管理用于教师创建课程、模块、资料和测验。
- 报名接口负责学生加入课程和教师管理学生状态。
- 模块进度接口负责记录学习状态。
- 资料上传支持小文件上传和分片上传。
- 测验接口支持教师出题、发布、学生尝试和结果查询。

### 通信服务

- 课程论坛按课程隔离。
- 帖子、评论和回复都需要校验课程访问权限。
- 通知支持管理员创建、用户读取、标记已读、隐藏和恢复。
- 内部通知接口供其他服务发送系统通知。

### AI 服务

- 对话接口支持课程和模块上下文。
- RAG 检索只允许访问当前用户有权限的资料。
- 索引任务由 worker 异步执行。
- 支持的 AI Provider 仅为 Gemini、GLM 和 OpenRouter；模型目录中不提供 DeepSeek。
- 用户只选择聊天模型，后端根据受控模型目录派生对应的 1024 维向量模型。
- 同一知识块可以保存多套模型向量，检索必须按向量模型和版本隔离。
- 学习画像由初始化和更新工作流维护。
- 测验生成分为教师草稿生成和学生自动尝试。
- 管理员 AI 观测接口提供调用量、失败审计、供应商状态和治理指标。

## 异步任务与存储

- Celery 使用 Redis 作为 broker 和结果存储。
- `learning-worker` 处理学习和测验相关任务。
- `communication-worker` 处理通知任务。
- `ai-worker` 处理资料索引、AI 工作流和任务恢复。
- MinIO bucket 应保持私有，资料访问由后端授权生成。

## 数据库

- MySQL 存放身份、学习和通信领域数据。
- PostgreSQL + pgvector 存放 AI 对话、知识库、向量和任务数据。
- schema 初始化位于 `database/`。
- 增量迁移位于 `database/migrations/`。

## 前端集成注意事项

- 前端请求统一走 nginx `/api`。
- 公开 API 响应字段以 camelCase 为主。
- AI 部分历史接口存在 snake_case 字段，前端 service 层负责归一化。
- 前端错误提示应显示用户可理解的中文，不暴露内部堆栈或密钥。
- 登录失效时应清理本地 session 并回到登录入口。

## 分层规则

- route/controller 负责 HTTP 边界。
- service 负责业务规则。
- repository 负责数据库访问。
- model 负责表映射。
- schema 负责请求和响应结构。
- core 负责配置、安全、密码、邮件和通用工具。
