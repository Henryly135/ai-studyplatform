# 后端测试说明

本文档记录后端测试方式、手动验证路径和常见失败排查。命令、接口路径、字段名和示例 token 名保持原样。

## 当前规则

- 公开 API 字段多数使用 camelCase，例如 `userName`、`accessToken`、`emailVerified`、`courseUuid`。
- AI 对话部分历史字段使用 snake_case，例如 `session_uuid`、`course_uuid`、`module_uuid`。
- 密码至少 8 位，并包含大写、小写、数字和特殊字符。
- 示例有效密码：`Password1!`。
- 前端和 nginx 默认地址通常是 `http://localhost:8080`。
- `identity-service` 暴露在 `/api`。
- `learning-service` 暴露在 `/api/learning`。
- `communication-service` 暴露在 `/api/communication`。
- `ai-service` 暴露在 `/api/ai`。

## 本地演示登录与 Gemini 冒烟

启动本地环境后，先执行不调用外部 Provider 的登录 HTTP 冒烟：

```powershell
.\scripts\smoke-local-demo.ps1
```

该脚本使用 `DEMO_LOGIN_EMAIL` / `DEMO_LOGIN_PASSWORD`（未设置时使用本地 demo 配置）登录，并要求 `/api/auth/login` 和 `/api/auth/me` 都成功。它不会输出 access token 或密码。

在已获准使用真实 Provider、且 Gemini Key 已安全注入容器的环境中，可额外执行最小真实健康检查：

```powershell
.\scripts\smoke-local-demo.ps1 -CheckGemini
```

该检查会临时切换本地 demo 的管理员角色执行 Gemini Provider 健康检查，并使用原始学员令牌完成一次最小聊天请求，以同时验证治理权限与普通对话权限；只输出 Provider/模型标识。不要在 CI、共享日志或未获授权环境中运行。

## 资料代理访问验证

课程响应中的平台托管资料现在应为 `/api/learning/materials/access/{materialUuid}` 短期代理 URL，而不是对象路径或 MinIO 预签名 URL。手动验证时：

1. 已注册且已解锁的学习者可以预览、Range 播放和下载资料。
2. 退课、锁定模块、停用账号后，已签发 URL 在下一次请求时返回拒绝。
3. 篡改 `materialUuid`、`userId`、身份、过期时间或签名时返回 `403`。
4. 通过 `GET /api/learning/materials/{materialUuid}/ticket`（带 Bearer token）刷新 URL；前端的定时和播放失败刷新也会重新取课程资料 URL。

外部链接保持原链接，不会被平台代理；不要将敏感外部资源配置为公开链接。

## 手动接口验证顺序

### 身份流程

1. 注册学生账号：`POST /api/auth/register`。
2. 注册教师账号或通过邀请链接注册教师。
3. 登录：`POST /api/auth/login`。
4. 查询当前用户：`GET /api/auth/me`。
5. 查询权限：`GET /api/auth/me/permissions`。
6. 修改密码和重置密码。
7. 管理员查询用户并修改用户状态。
8. 管理员处理教师审批或生成教师邀请。

### 学习流程

1. 教师创建课程：`POST /api/learning/courses`。
2. 教师创建模块：`POST /api/learning/courses/{course_uuid}/modules`。
3. 教师上传资料。
4. 教师发布模块和课程。
5. 学生查询课程目录并加入课程。
6. 学生打开模块并更新学习进度。
7. 教师创建和发布测验。
8. 学生开始测验、提交答案、查询结果。

### 通信流程

1. 学生或教师创建课程论坛帖子。
2. 查询帖子列表和详情。
3. 创建评论和回复。
4. 管理员或系统创建通知。
5. 用户查询通知、标记已读、隐藏和恢复。

### AI 流程

1. 管理员分别保存 Gemini、GLM、OpenRouter Key 并执行健康检查。
2. 确认模型目录中不存在 DeepSeek，聊天模型都带有后端派生的配对向量模型。
3. 上传资料后检查索引任务，等待三套 1024 维向量覆盖率达到 100%。
4. 在同一课程上下文依次选择 Gemini、GLM、OpenRouter 聊天模型。
5. 验证每次请求的 `model_id` 都对应页面显示的聊天 `modelId`。
6. 验证查询向量使用该聊天模型配对的 Embedding，检索只命中相同模型与版本。
7. 验证响应返回实际聊天模型、向量模型、检索模式和资料来源。
8. 验证切换聊天模型不会触发临时资料重建。
9. 验证无权限用户不能检索其他课程资料。
10. 教师生成测验草稿，确认检索和生成使用管理员默认模型组合。
11. 学生开始自动生成测验尝试。
12. 管理员查看 AI 运行状态、索引覆盖率、失败审计和供应商健康状态。

## 常见失败排查

### `401`

- token 缺失。
- token 已过期。
- 请求头不是 `Authorization: Bearer <token>`。

### `403`

- 当前角色无权限。
- 教师操作了不属于自己的课程。
- 学生访问了管理接口。
- 管理员接口未使用管理员账号。

### `422`

- 请求字段缺失。
- 字段类型不匹配。
- 枚举值不在允许范围内。

### AI 服务不可用

- 管理员尚未配置对应 Gemini、GLM 或 OpenRouter Key。
- 聊天模型对应的向量模型仍在回填或回填失败。
- 外部模型服务不可用或额度不足。
- PostgreSQL/pgvector 初始化失败。
- Redis 或 worker 未启动。

### MinIO 上传失败

- bucket 未初始化。
- 上传大小超过限制。
- nginx 代理路径不正确。
- 后端未生成授权访问地址。

## Provider Contract 测试要求

标准测试不能调用真实付费 API，应使用可控 HTTP Stub 覆盖：

- 正常文本和 JSON 响应。
- 401、402、429、5xx 和超时。
- HTTP 200 但响应体携带 `error`。
- 非 JSON、缺少结果字段和向量维度错误。
- Provider Key 保存、覆盖、脱敏、删除与权限校验。
- Gemini、GLM、OpenRouter 单 Provider 完整索引和检索路径。
- 一个 Provider 回填失败时，其他 Provider 向量仍可使用。
- 相同知识块、模型和版本重复回填保持幂等。

真实 Provider 冒烟测试只在受保护环境中手动执行，使用最小请求，并禁止把提示词、完整响应或 Key 写入日志。
