# AI 与 LangChain 架构说明

本文档记录 AI 服务中 LangChain、Gemini、RAG、画像更新和测验生成的职责划分。配置名、模型名和代码路径保持原样。

## 运行路径

AI 服务默认使用 LangChain 作为编排层：

```env
AI_CHAT_ORCHESTRATOR=langchain
AI_EMBEDDING_ORCHESTRATOR=langchain
```

旧的直接调用 Google SDK 路径只作为应急兜底。需要临时绕过 LangChain 时，可以把对应编排配置改成非 `langchain` 的值，例如 `legacy`。

## 职责划分

LangChain 负责：

- 普通对话提示词组装。
- RAG 上下文提示词组装。
- 对话历史注入。
- Gemini 聊天模型调用。
- 输出解析。
- 查询向量和文档向量生成。

PostgreSQL 与 pgvector 负责：

- 对话会话和消息持久化。
- 隐藏的检索上下文消息。
- 知识源和知识块存储。
- 向量相似度检索。

FastAPI 服务层负责：

- 鉴权和角色权限校验。
- 课程、模块、资料和用户上下文校验。
- 数据库事务边界。
- 错误转换和前端响应格式。

Celery worker 负责：

- 学习资料索引。
- 异步测验生成。
- 学习画像更新。
- 停滞任务恢复和重试。

## 主要工作流

1. 教师上传或更新课程资料。
2. 学习服务创建资料记录，并通知 AI 服务创建索引任务。
3. AI worker 从 MinIO 或本地存储读取资料。
4. 文本被切分、嵌入并写入 PostgreSQL + pgvector。
5. 学生在课程或模块中提问。
6. AI 服务校验访问权限后检索授权范围内的知识块。
7. LangChain 组装提示词并调用 Gemini。
8. 响应和检索上下文被记录，用于审计和后续画像更新。

## 校验重点

- RAG 只能检索用户有权限访问的课程资料。
- 资料索引失败要记录任务状态和错误原因。
- LLM 或嵌入服务不可用时要返回可理解的错误。
- 学习画像更新不能覆盖人工可解释的核心字段。
- 测验生成结果必须经过题目数量、选项、答案和解析校验。
